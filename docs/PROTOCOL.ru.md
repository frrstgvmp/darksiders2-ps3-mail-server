# Почтовый протокол и его реализация

[English](PROTOCOL.md) · **Русский** · [Главная](../README.ru.md)

Здесь описана реализованная часть протокола, а не полная спецификация
THQ Connect. В примерах используются вымышленные профили, билеты не приводятся.

## Маршрутизация и транспорт

Для точных настроенных имён THQ сервер возвращает свой IPv4 в DNS A-ответах.
Публичный DNS передаёт дальше только IN A/AAAA в семействах доменов игры/PSN,
перечисленных в [PUBLIC-SERVER.ru.md](PUBLIC-SERVER.ru.md). Остальные запросы
получают REFUSED. UDP/TCP ограничены по размеру и частоте. Закрытый режим
дополнительно ограничивает исходные IPv4. Допуск и ограничения частоты HTTPS
проверяются до обработки TLS ограниченным числом рабочих потоков.

Наблюдавшийся Cloud-узел: `thqc-darksiders2-ps3-na.thqconnect.com:8443`.
Европейское издание также использовало этот NA-узел. Для других регионов нужен
захват клиента: одного перенаправления DNS недостаточно, чтобы добавить имя
в сертификат. GDS использует `ds2.gds.thqconnect.com:443`; его протокол
не входит в реализацию почты.

Поддерживаются GET и POST с формой на `/thqconnect/cloud/execute`.
Обязательны `version=1`, `platform=PS3_PSN`, `title=Darksiders2`.
В публичном режиме нужен ровно один билет Base64 в `auth`: проверяются подпись
по закреплённому публичному ключу PSN, личность, игровой сервис и срок.
Закрытый режим включает ту же проверку через `verify_psn_tickets:true`.
При отказе авторизации возвращается 403; health доступен анонимно.
Поля POST и строки запроса объединяются, повтор обязательных параметров
отвергается. Принимаются тела с Content-Length до 64 КиБ публично
или 512 КиБ в закрытом исследовательском режиме; chunked не поддерживается.

## Операции и пакеты

`profileNames`, `ops`, `docKeys`, `keys`, `values` — согласованные списки через
запятую. Пустые позиции нужно сохранять. Пакет содержит 1–64 операции.
`policy`, `worldPerms`, `friendPerms` могут быть одним значением либо списком
по числу операций. Экранирование запятой внутри отдельного значения пакета
этой ограниченной реализацией не предусмотрено.

Профиль — `/psn/` и 1–32 латинские буквы, цифры, `_` или `-`; хранится
в нижнем регистре. Поддерживаются `TomeGift`, `TomeGiftJP` (ящик японской BLJS10199) и `GameToWeb`.
Два почтовых документа хранятся раздельно; правила авторизации, проверки
пакетов, повторов и квоты одинаковы. Подарки между ними автоматически
не переносятся. Межрегиональная пересылка пока не подтверждена.

| Операция | Поведение |
| --- | --- |
| `GET` | Полная карта документа и метаданные |
| `SET`, пустое значение | Инициализация/обновление метаданных с сохранением подарков |
| `SET`, значение JSON-объект | Замена карты строковых значений; для обоих авторизованных почтовых документов запрещена |
| `REMOVE` | Удаление документа целиком |
| `MAP_GET` | Полная карта в формате массива SDK с автором/датой каждого ключа; чтение одного ключа не реализовано |
| `MAP_SET` | Сохранение непрозрачного пакета под непустым ключом; для авторизованного подарка действуют проверки оболочки и квоты |
| `MAP_REMOVE` | Удаление ключа; отсутствие ключа не является ошибкой |
| `SET_PERM` | Обновление сохранённых метаданных прав |

GET/SET, MAP_GET/MAP_SET и MAP_REMOVE наблюдались у игры. Клиент загружает
подарки в локальное хранилище и автоматически удаляет соответствующие ключи
из облака **до получения предмета в инвентарь**. MAP_REMOVE этого получения
не доказывает. REMOVE и SET_PERM реализованы, но не заявляются как наблюдавшиеся
игровые сценарии. Биты дружбы/публичного доступа принимаются, но не проверяются
через PSN. При авторизации `modified_by` — подписанный отправитель;
в старом режиме без авторизации — целевой профиль.

Весь пакет проверяется до изменения базы. Изменения идут в транзакции SQLite
`BEGIN IMMEDIATE` и фиксируются до ответа. Поздняя ошибка отменяет предыдущие
изменения пакета. Пустое чтение возвращает пустую карту. Пакеты подарков
хранятся без изменений. Проверяются ограниченные оболочки Base64/BOD,
но не полная семантика предметов; содержимое не синтезируется.

Удалить документ целиком может только подписанный владелец. Непустой
`SET` с непустым значением для обоих почтовых документов запрещён; пустая инициализация сохраняет записи. Отправитель
может добавить подарок другому профилю, но не читать/удалять его почту.
Существующий ключ подарка допускает только идентичный повтор. Ответ чужому
профилю содержит лишь отправленную запись. Привязка аккаунт–профиль защищает
владение. Нарушение квот отменяет весь пакет; см. [ограничения](PUBLIC-SERVER.ru.md).

## Ответ версии 1

Используется позиционный JSON; документ внутри него — строка JSON:

```json
[0, [[0, "{}", 0, 0, ""]]]
```

Внешний массив: `[resultCode, documents]`. Документ:
`[status, documentJsonString, policyBits, lastModifiedSeconds, lastModifiedProfileName]`.
Ответ пустого ящика выше занимает 22 байта с переводом строки и принят игрой.
GET возвращает сохранённую компактную карту; непустой MAP_GET — массив записей
SDK в строке JSON и внешние метаданные. Добавление в чужой ящик возвращает
только отправленную запись и метаданные операции. Время — Unix-секунды;
оригинальный читатель использует знаковое 32-битное число.

Подарок отправляется через `MAP_SET`, документ `TomeGift`
(у наблюдавшегося японского клиента — `TomeGiftJP`), адресата
в `profileNames`, идентификатор в `keys` и пакет в `values`. Он сохраняется
без изменений. HTTP 200 выдаётся после фиксации транзакции. Проверки протокола и хранения выполняются автотестами;
результаты OFW приведены в [STATUS.ru.md](STATUS.ru.md).

Неподдерживаемые/запрещённые запросы с действующей авторизацией получают 503,
неверные/отсутствующие билеты — 403. Проверка билета предшествует почтовым
операциям. login/platformLogin, login/ssoStatus, news/getNews, GDS и неизвестные
cloud-операции не реализованы. Код 503 сам по себе не означает ошибку TLS:
транспорт и приложение нужно различать по журналам.

## База данных

Таблица `documents`:

```sql
CREATE TABLE documents (
  profile TEXT NOT NULL,
  name TEXT NOT NULL,
  data TEXT NOT NULL,
  policy INTEGER NOT NULL,
  modified INTEGER NOT NULL,
  modified_by TEXT NOT NULL,
  PRIMARY KEY (profile, name)
);
```

В `documents.data` остаётся компактный JSON вида «ключ → неизменённая строка
пакета». Для непустого MAP_GET сериализатор создаёт массив SDK версии 1
(этот массив затем помещается в строку JSON внешнего ответа):

```json
[["gift-id", ["opaque-base64", "/psn/sender", 1700000000]]]
```

Запись — `[key, data]`, данные — `[value, lastModifiedName, lastModifiedDate]`.
Версия 1 читает позиции, поэтому объекты с именованными полями не заменяют
эти массивы. Для пустой карты сохранено проверенное `"{}"`.
Оригинальные читатели: `0x65dfec` (key/data), `0x65dddc` (value/name/date),
вызываемые читателем вектора `0x11fe930`. Плоский непустой словарь отвергался
игрой при успешных TLS, авторизации и HTTP 200. Позиционный формат позволил
получить предмет. Письмо без Gift/Items не имеет вложения: Delete-only
не следует путать с ошибкой транспорта.

Метаданные ключа хранятся отдельно:
`map_metadata(profile,name,key,modified,modified_by)` с составным первичным
ключом. Старые записи при первом обращении наследуют метаданные документа
до их изменения инициализацией. Новые записи получают подписанного автора
и дату. Повторы и пустая инициализация сохраняют метаданные ключей;
удаление очищает их транзакционно. На пакет открывается соединение SQLite,
локальные операции сериализуются. Транзакции предотвращают потерю записей
между экземплярами хранилища. Копирование использует SQLite backup API,
а не простое копирование работающего файла.

Для авторизации добавлена таблица:

```sql
CREATE TABLE profile_owners (
  profile TEXT PRIMARY KEY,
  account_id TEXT NOT NULL
);
```

Владелец записывается транзакционно при первом авторизованном обращении.
Попытка другого аккаунта присвоить связанный профиль отвергается. Смена
Online ID и удаление данных пока требуют процедуры оператора; веб-интерфейса
миграции нет. Старые исследовательские документы остаются, последующие
подписанные операции подчиняются описанным правилам.
